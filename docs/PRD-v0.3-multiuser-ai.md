# 栗知自习室 v0.3 需求文档：多用户、知识库与 AI 平台化

> v1.0 草案 · 2026-10-08 · 基线 v0.2.1 · 作者 yunyancuo（RC-Friends）· 状态：待评审

## 1. 背景与目标

当前系统为单账户架构：全站共用一个登录口令，仅存在一名考生；模型接入由服务端环境变量统一配置；题库导入依赖命令行脚本。本版本将系统演进为多用户学习平台，并围绕知识库与 AI 能力进行扩展，共六个需求域：

| 需求域 | 概述 |
| --- | --- |
| A 多用户与权限 | 邀请制注册、数据隔离、公开档案、管理后台 |
| B 题库管理界面 | 将既有题库导入 API 产品化为 Web 界面 |
| C 知识库 | 备考资料的上传、解析与管理，作为 AI 出题素材 |
| D AI 运营商接入 | 用户自带密钥（BYOK），多运营商并存与加密管理 |
| E AI 出题 | 弱项智能组卷、知识库生成题目、学习情况定向出卷 |
| F 开放接口与机器人 | 长期 API 凭证与机器人专用接口，接入 AstrBot |

成功标准：多用户数据严格隔离且公开性由用户自主控制；管理员全程通过 Web 完成站点管理；用户配置自有模型密钥后即可用于对战与陪练；机器人可完成"出题—作答—报告"闭环且凭证可吊销。

## 2. 需求域 A：多用户与权限管理

账户采用**邀请制**：管理员签发邀请码，受邀者自行完成注册（是否同时提供开放注册开关见待定事项）。

- **A1 账户体系**：用户名 + 口令登录，独立 JWT（`sub` 为真实用户标识）；口令变更仅使本人会话失效。
- **A2 数据隔离**：答题记录、错题本、收藏、笔记、学习档案与统计全部按用户隔离，任何接口不可跨用户读写。
- **A3 公开档案**：用户可将个人学习档案设为公开（默认关闭），游客与其他用户可查看其总览、统计与已完成练习；关闭后立即对外不可见。公开内容沿用现有脱敏规则，不含笔记与进行中场次。
- **A4 围观与监督**：提供公开档案列表页（昵称、连续打卡、本周正确率），支持搜索，延续"公开监督"产品理念。
- **A5 管理后台**：邀请码签发与吊销、用户列表、启用/停用（停用即拒绝登录并使会话失效）、角色管理。
- **A6 审计日志**：记录登录、管理操作、题库与知识库发布、API 凭证变更；只追加、可查询，不包含任何密钥明文。
- **A7 存量迁移**：升级时现有单用户数据自动归属站主账户；迁移幂等、先校验后执行。

实现要点：数据库各表已含 `owner_id` 字段且 JWT 标识已贯通至服务层，改造集中在移除服务层对单一用户（`primary`）的硬编码假设、将全局写锁与全局缓存修订号改为按用户粒度。

## 3. 需求域 B：题库管理界面

复用既有题库导入 API（校验、分片上传、原子发布），补齐界面与任务化能力：

- **B1 导入向导**：上传标准导入 JSON 与图片，提交结构校验；校验未通过不得进入上传步骤。
- **B2 错误定位**：校验失败时逐条展示错误（题号、字段、原因），支持导出失败清单。
- **B3 任务与进度**：导入过程持久化为任务记录（状态、进度、发起人、错误快照），页面关闭后可再次查看；后端重启不丢任务状态。
- **B4 发布确认**：上传完成后展示版本摘要（题目数、图片数、新增与复用数量），管理员确认后发布并即时生效，无需重启；版本冲突时给出增量合并指引。
- **B5 版本视图**：展示当前生效版本与历史版本列表。

界面沿用学习中心现有设计语言，入口仅管理员角色可见。

## 4. 需求域 C：知识库

知识库为 AI 出题提供素材，一期为**全局共享库**（管理员上传、全体考生可用）。

- **C1 上传**：支持 Markdown / TXT / PDF，单文件 ≤ 32 MiB，同内容按 SHA-256 去重秒传；扫描版 PDF 无可提取文本时明确报错并标注页码。
- **C2 解析入库**：抽取纯文本并切分为片段（目标 500–1000 字，携带章节/页码锚点）；元数据与片段存储于 PostgreSQL，原文存对象存储（沿用现有 S3 内容寻址与只读/读写凭证分离机制）。
- **C3 管理页**：文档列表、预览、删除（级联清理片段）、模块标签管理。
- **C4 变更审计**：文档增删记入审计日志，并触发 AI 出题相关缓存失效。

一期不做：EPUB/Office 解析、OCR、向量检索（RAG 列入二期评估）、个人私有知识库。

## 5. 需求域 D：AI 运营商接入（BYOK）

- **D1 运营商配置**：用户在设置页维护多个 OpenAI 兼容配置（名称、Base URL、API Key、模型、可选参数），支持启停、删除与连通性测试。
- **D2 加密存储**：API Key 以 AES-256-GCM 加密落库，主密钥来自服务端环境变量（部署脚本生成）；接口回显仅末四位；主密钥未配置时 BYOK 功能整体停用并明确提示。
- **D3 调用链改造**：模型配置由全局单例改为按请求按用户注入；对战与陪练均可选择本人启用的模型；调用失败沿用现有"不自动重跑、手动重试"语义。
- **D4 平台默认与降级**：站主环境变量配置作为平台默认模型（可配置是否允许用户回退使用）；演示对战模式保留；无任何可用模型时仅提供演示模式。
- **D5 用量与限额**：按用户按配置统计调用次数与失败数；每用户每日模型调用上限默认 500 次（站主可调），超限返回明确错误与重置时间。

安全边界：密钥仅在服务端内存解密使用，不进入日志、推送与前端回显；审计仅记录调用结果，不记录内容。

## 6. 需求域 E：AI 出题

### 6.1 设计原则（2026-10-08 与产品负责人确认）

- **命题学科不限**：不限于考公六大模块——考研、职业考试等任意学科，以用户知识库内容为准；行测模块字段降级为可选标签。
- **无审核环节**：生成的题目直接进入练习，不设事前人工审核。
- **反馈在做题中**：题目质量差由做题时的「此题不好，换一题」表达，而不是事后审核。

### 6.2 功能需求

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-E1 | **弱项加权组卷**：从现有题库按模块正确率反向加权、错题优先、同知识点去重 | 组卷可解释（展示构成）；同参数同卷 |
| FR-E2 | **自由主题即时命题**：用户手动描述主题（如「我想写点行程问题的题目」）+ 题量 → RAG 检索知识库相关片段 → 模型生成 → **立即开始练习** | 严格基于检索片段命题，解析引用出处；任意学科可用；生成失败有明确提示 |
| FR-E3 | **做题中反馈换题**：练习中一键「此题不好，换一题」——当前题即时作废并生成替换题 | 替换题保持同一主题；被换题目记录为低质反馈，沉淀用于命题质量优化 |
| FR-E4 | **用量与防泄漏**：生成调用计入每用户限额；生成内容严格基于检索片段 | 超限明确提示；无相关片段时拒绝命题并说明 |

### 6.3 说明

- 第一版（已实现本地验证）：主题 + 模块 + 题量 → 生成 → 待审核草稿区。v2 按上述原则重构：去掉审核流，题目直接进练习，反馈移到做题中。
- 模型不可用时 E1 恒可用；E2/E3 提示需配置模型服务。

## 7. 需求域 F：开放接口与 AstrBot 集成

- **F1 长期 API 凭证**：用户可生成、命名、吊销机器人专用 API Key（`liz_` 前缀，仅创建时明文展示一次，服务端仅存哈希）；吊销即时生效，不影响网页端登录。
- **F2 机器人接口**：新增 `/api/bot/*` 端点族，以 API Key 鉴权（与网页 JWT 完全独立），独立限流键空间；提供出题、作答提交、学习报告、错题提醒数据源四类能力。
- **F3 作答语义**：机器人渠道作答计入本人学习统计，并携带来源标记（`channel=bot`）以便区分；防重复作答沿用现行判分语义。
- **F4 接口契约**：全部端点提供 OpenAPI 描述并版本化，破坏性变更升版本路径；AstrBot 插件以独立仓库交付，本仓库仅承诺 HTTP 契约。

不做：机器人代替网页端管理操作；一个凭证对应多个用户；服务端主动推送（提醒由插件轮询实现）。

## 8. 非功能性要求

- **安全**：密钥加密方案（含篡改检测、缺主密钥行为）需单元测试覆盖；三套凭证体系（登录 JWT、管理令牌、机器人 Key）限流键空间互不影响。
- **隔离**：新增双用户交叉操作的集成测试（并发练习、笔记、对战），验证 403/404 与数据归属。
- **性能**：写路径按用户加锁后，10 并发用户下 P95 写延迟不超过现单用户基线的 1.5 倍。
- **兼容**：提供 v0.2.x 原地升级路径，迁移含空库、有数据、重复执行三类验证；文件存储模式声明为单用户开发用途，多用户能力仅在生产模式（PostgreSQL + Redis）下启用。
- **质量门槛**：各需求域在单元与集成测试中有对应覆盖，全栈验收纳入 CI。

## 9. 实施排期

| 里程碑 | 内容 | 依赖 | 验收标志 |
| --- | --- | --- | --- |
| M1 | 需求域 A（多用户与权限） | — | 双用户隔离测试全绿，存量迁移通过 |
| M2 | 需求域 B + 管理后台界面 | M1 | 全程 Web 完成含图题库发布 |
| M3 | 需求域 D（BYOK） | M1 | 两名考生分别使用自有运营商完成对战 |
| M4 | 需求域 C（知识库） | M1，可与 M3 并行 | 上传 PDF 至片段预览、删除级联全通 |
| M5 | 需求域 E（AI 出题） | M3、M4 | 自由主题命题直接进练习；做题中换题反馈可用 |
| M6 | 需求域 F（机器人） | M1、M5 | 聊天内完成出题—作答—报告闭环，凭证可吊销 |

每期独立可发布，不设联合上线依赖。

## 10. 待定事项

1. 是否提供开放注册开关（倾向：保留开关，默认邀请制）。
2. 管理员是否支持多人协作（倾向：一期仅站主，角色字段预留）。
3. 个人私有知识库是否纳入二期（倾向：纳入评估）。
4. RAG 检索选型（倾向：pgvector，减少外部依赖）。
5. AI 生成内容的来源版权责任边界（倾向：服务条款约束；质量由做题中「换一题」反馈机制治理）。
6. 机器人每日调用限额默认值（倾向：500 次，上线后依数据调整）。
